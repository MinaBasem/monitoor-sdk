Screen Views

Screen view tracking tells you which screens your users visit and how often. It records only the name of the screen as a string — no screenshots, no recordings, no visual content of any kind.

ℹ️
Screen tracking sends a $screen_view event with a $screen_name property. It is identical in structure to any other event and is stored in the same Event table.

UIKit — automatic (no code required)

When captureScreens: true (the default), the SDK swizzles UIViewController.viewDidAppear(_:) at startup. Every time a view controller appears, a $screen_view event fires automatically.

The screen name is derived from the view controller's class name with common suffixes stripped:

Class nameTracked as
LibraryViewControllerLibrary
PlaylistDetailVCPlaylistDetail
NowPlayingControllerNowPlaying
SettingsVCSettings

Stripped suffixes: ViewController, Controller, VC.

System containers are excluded automatically and do not generate screen view events:

  • UINavigationController
  • UITabBarController
  • UIPageViewController
  • UISplitViewController
  • UIInputViewController
  • UIAlertController

SwiftUI — .monitoorScreen() modifier

SwiftUI does not use UIViewController for every screen, so automatic tracking does not apply to SwiftUI views. Attach the .monitoorScreen() modifier to each screen-level view instead.

Basic usage

struct LibraryView: View {
    var body: some View {
        List(tracks) { TrackRow(track: $0) }
            .monitoorScreen("Library")
    }
}

With properties

struct PlaylistDetailView: View {
    let playlist: Playlist

    var body: some View {
        ScrollView { /* content */ }
            .monitoorScreen("PlaylistDetail", properties: [
                "name":        playlist.name,
                "track_count": playlist.trackIds.count
            ])
    }
}

Tracking sheets and modals

struct NowPlayingView: View {
    var body: some View {
        VStack { /* player UI */ }
            .monitoorScreen("NowPlaying")
    }
}

// The .sheet presentation — track the sheet as its own screen
.sheet(isPresented: $showNowPlaying) {
    NowPlayingView()  // .monitoorScreen is inside NowPlayingView
}

Tracking tab-based navigation

struct RootView: View {
    @State var selectedTab: AppTab = .library

    var body: some View {
        ZStack {
            switch selectedTab {
            case .library:
                LibraryView()    // has .monitoorScreen("Library")
            case .playlists:
                PlaylistsView()  // has .monitoorScreen("Playlists")
            case .settings:
                SettingsView()   // has .monitoorScreen("Settings")
            }
        }
    }
}

Manual tracking

Call Monitoor.screen() directly when you need full control, for example in response to a programmatic navigation event:

Monitoor.screen("OnboardingStep3")

Monitoor.screen("StockDetail", properties: ["symbol": "AAPL"])

Disabling automatic screen tracking

To disable UIKit's automatic swizzle while keeping manual tracking available:

Monitoor.configure(
    apiKey: "mn_live_...",
    options: MonitoorOptions(
        captureScreens: false  // disables the UIKit swizzle
    )
)
💡
Name consistency matters. If the same screen is tracked as "Library" in some places and "LibraryView" in others, the dashboard will show them as two separate screens. Pick a convention and stick to it.
