Identity

User Identity

The SDK is anonymous by default. Optionally link events to your own user IDs and attach non-PII attributes. All user IDs are hashed on-device before leaving the app.

How identity works

The SDK uses two identifiers:

IdentifierTypeLifetimeNotes
device_idUUID (auto-generated)Permanent, survives app updatesStored in iOS Keychain. Not linked to Apple ID or any real identity. Reset on Monitoor.reset().
user_id_hashSHA-256 hex string (opt-in)Until reset() is calledSHA-256 of your user ID, hashed on-device. Monitoor never receives the plaintext ID.

identify()

Call after the user signs in to link events to a specific user. All subsequent events will carry the hashed user ID.

// In your sign-in completion handler
func didSignIn(user: User) {
    Monitoor.identify(userId: user.id)
}

// With SwiftUI state
.onChange(of: authManager.currentUser) { _, user in
    if let user {
        Monitoor.identify(userId: user.id)
    } else {
        Monitoor.reset()
    }
}
⚠️
Do not pass PII as the user ID. Do not pass an email address, phone number, or any other directly identifying string. Pass your internal user ID (a UUID or opaque numeric ID). Even though it is hashed, it is best practice not to use reversible identifiers.

setUserProperties()

Attach non-PII attributes that describe the user's account state. These are not sent as their own events — they are attached to the user identity and can be used in the dashboard to segment events.

// Set after sign-in or when user state changes
Monitoor.setUserProperties([
    "plan":              "pro",
    "account_age_days":  120,
    "has_2fa":           true
])

// Update when subscription changes
func onSubscriptionChanged(to plan: Plan) {
    Monitoor.setUserProperties(["plan": plan.rawValue])
    Monitoor.track("subscription_changed", properties: ["plan": plan.rawValue])
}

Properties are merged — calling setUserProperties() multiple times adds to the existing set. Later values overwrite earlier ones for the same key:

Monitoor.setUserProperties(["plan": "free"])
Monitoor.setUserProperties(["plan": "pro"])  // overwrites "free"

// Result: plan = "pro"

reset()

Clears all user identity, generates a new anonymous device_id, and starts a new session. Use on sign-out so future events cannot be correlated with the previous user.

func signOut() {
    auth.signOut()
    Monitoor.reset()
    // A fresh $app_open event is sent with the new device_id
}
ℹ️
reset() generates a new Keychain-stored device_id. After calling it, there is no way to re-link events before and after the reset. This is by design.

Full sign-in / sign-out flow

// On app start — SDK is anonymous until the user signs in
Monitoor.configure(apiKey: "mn_live_...")

// After successful sign-in
func onSignInSuccess(user: User) {
    Monitoor.identify(userId: user.id)
    Monitoor.setUserProperties([
        "plan": user.plan,
        "locale": user.locale
    ])
    Monitoor.track("sign_in_completed", properties: [
        "method": "email"
    ])
}

// After sign-out
func onSignOut() {
    Monitoor.track("sign_out_tapped")
    auth.signOut()
    Monitoor.reset()  // clears identity, new anonymous device
}
