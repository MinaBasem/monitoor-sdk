MonitoorOptions

Configuration

All SDK behaviour is controlled through MonitoorOptions, passed to Monitoor.configure(). Every option has a sensible default — only override what you need.

Full configuration example

Monitoor.configure(
    apiKey: "mn_live_your_key_here",
    options: MonitoorOptions(
        ingestURL:          URL(string: "https://ingest.monitoor.io")!,
        environment:        .production,
        captureEvents:      true,
        captureScreens:     true,
        captureRevenue:     true,
        captureCrashes:     true,
        captureHeatmaps:    false,   // opt-in
        captureRecordings:  false,   // opt-in
        sampleRate:         1.0,
        retentionDays:      90,
        flushInterval:      30,      // seconds
        flushBatchSize:     10,      // events per request
        sessionTimeout:     30 * 60  // 30 minutes
    )
)
ℹ️
These values are local defaults. The capture flags, sampleRate, and retentionDays are overridden at runtime by remote configuration fetched from your dashboard. The remaining options (flushInterval, flushBatchSize, sessionTimeout, ingestURL, environment) are local-only.

Remote configuration

On startup the SDK calls GET /v1/config and applies your API key's capture configuration at runtime. This lets you change behaviour from the dashboard without shipping an app update:

  • Toggle captureEvents, captureScreens, captureRevenue
  • Adjust the sampling rate (the mul column → sampleRate)
  • Change retention (→ retentionDays)

The local MonitoorOptions values are used as fallbacks until the remote config arrives, and whenever the device is offline. Once fetched, server values take precedence for the runtime-toggleable flags.

⚠️
Installation vs. runtime gating. Crash handlers, the StoreKit observer, and the UIKit screen swizzle are installed once at launch from your local options. A remote value of true cannot enable something that was never installed — but a remote false cleanly suppresses capture at runtime.

Option reference

ingestURL

TypeDefault
URLhttps://ingest.monitoor.io

The base URL of the Monitoor ingest service. All event batches are posted to {ingestURL}/v1/ingest. Change this to your local server address during development.

environment

TypeDefault
MonitoorOptions.Environment.production

Must match the prefix of your API key:

EnvironmentRequired key prefixUse for
.productionmn_live_App Store, TestFlight
.developmentmn_dev_Local dev, Simulator

A mismatch causes configure() to abort and log an error. Events tagged development are filtered out of production dashboards.

captureEvents

TypeDefault
Booltrue

When true, calls to Monitoor.track() and .monitoorTap() are captured. Set to false to disable all custom event tracking (for example, during an A/B test where you want to reduce data volume).

captureScreens

TypeDefault
Booltrue

When true, screen view events are captured. In UIKit, this is fully automatic via a method swizzle on UIViewController.viewDidAppear(_:). In SwiftUI, attach .monitoorScreen("Name") to your views. This option maps to the captureScreens column on your ApiKey record.

captureRevenue

TypeDefault
Booltrue

When true, all verified StoreKit 2 transactions are captured automatically. Manual calls to Monitoor.trackRevenue() always work regardless of this setting.

captureCrashes

TypeDefault
Booltrue

When true, the SDK installs signal handlers (SIGABRT, SIGSEGV, SIGBUS, SIGILL, SIGFPE, SIGTRAP) and an uncaught exception handler. Crash reports are stored on disk and uploaded on the next app launch.

⚠️
Crash handler conflicts. If you use another crash reporting SDK alongside Monitoor, both can coexist as long as each saves and re-raises the signal. Monitoor preserves the previously installed exception handler and re-raises signals after writing the report.

captureHeatmaps

TypeDefault
Boolfalse

Opt-in. Privacy-sensitive. Not yet implemented. Reserved for click heatmap capture in a future release.

captureRecordings

TypeDefault
Boolfalse

Opt-in. Privacy-sensitive. Not yet implemented. Reserved for session recording in a future release. Does not capture any visual content until implemented.

sampleRate

TypeDefaultRange
Double1.00.0 – 1.0

Controls what fraction of developer events are actually recorded. 1.0 sends every event. 0.5 randomly drops ~50% of events. This mirrors the mul column on your ApiKey record, which the ingest service uses for statistical weighting.

ℹ️
System events prefixed with $ (such as $app_open, $app_background, $screen_view) are never sampled out, regardless of sampleRate.

retentionDays

TypeDefault
Int90

Maximum number of days an unsent event is kept in the local SQLite buffer. Events older than this are pruned automatically. This mirrors the retention column on your ApiKey record.

flushInterval

TypeDefault
TimeInterval (seconds)30

How often the SDK's timer fires to flush buffered events. The timer only sends a request when there are pending events — an idle tick produces no HTTP call. Batch-full and lifecycle triggers fire independently of this timer.

flushBatchSize

TypeDefault
Int10

Maximum number of events sent in a single HTTP request. When the buffer reaches this count, a flush is triggered immediately regardless of the timer. Each flush drains the entire buffer in consecutive batches of this size.

sessionTimeout

TypeDefault
TimeInterval (seconds)1800 (30 min)

If the app remains in the background longer than this interval before returning to the foreground, a new session is started. The previous session's $session_duration_s is attached to the $app_background event automatically.
