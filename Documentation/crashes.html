Crash Reporting

Capture signal-level and exception-level crashes without any code changes. Reports include a full stack trace and are uploaded automatically on the next app launch.

Setup

Crash reporting is enabled by default. No additional code is required beyond calling Monitoor.configure():

Monitoor.configure(
    apiKey: "mn_live_...",
    options: MonitoorOptions(
        captureCrashes: true  // default
    )
)

What is captured

The SDK installs two types of handlers:

Handler typeCatches
NSSetUncaughtExceptionHandlerUncaught Swift/Objective-C exceptions (e.g., fatalError, preconditionFailure, unhandled NSException)
sigactionSIGABRT, SIGSEGV, SIGBUS, SIGILL, SIGFPE, SIGTRAP

Crash report flow

1. Crash occurs
      ↓
2. Signal or exception handler fires
      ↓
3. Handler writes crash report to disk
   (async-signal-safe: only write() syscall, no malloc, no ObjC)
      ↓
4. Process exits / re-raises signal
      ↓
5. NEXT app launch:
      SDK scans Caches/monitoor_crashes/ for pending .json files
      Uploads each to POST /v1/crashes before any other events
      Deletes the file on successful upload
⚠️
Reports upload on the next launch, not during the crash. This is intentional — the process is in an undefined state after a crash and it is unsafe to make network calls at that point.

What a crash report contains

FieldDescription
exception_typeSignal name or exception type (e.g. EXC_BAD_ACCESS)
exception_nameSignal name (e.g. SIGSEGV)
reasonHuman-readable reason string
session_idThe session in which the crash occurred
device_idAnonymous device identifier
app_versionApp version at time of crash
os_versioniOS version
deviceDevice model
occurred_atTimestamp of the crash
threadsArray of thread backtraces with frame addresses

Symbol resolution (dSYM)

Crash frames are captured as raw memory addresses. Without the debug symbol file (.dSYM), frames appear as hex addresses. Upload your dSYM after each build to symbolicate them into readable function names and line numbers.

# Upload dSYM after building
curl -X POST https://ingest.monitoor.io/v1/apps/YOUR_APP_ID/dsym \
  -H "Authorization: Bearer mn_live_..." \
  -F "file=@/path/to/YourApp.app.dSYM.zip" \
  -F "build_uuid=YOUR_BUILD_UUID" \
  -F "app_version=2.1.0" \
  -F "build=214"

Find your build UUID:

xcrun dwarfdump --uuid /path/to/YourApp.app/YourApp
💡
Add the dSYM upload command to your Xcode build scheme's post-action script or your CI pipeline so it runs automatically on every build.

Disabling crash reporting

Monitoor.configure(
    apiKey: "mn_live_...",
    options: MonitoorOptions(
        captureCrashes: false
    )
)

Using alongside other crash reporters

Monitoor preserves any previously installed exception handler and re-raises signals after writing its own report, so it is safe to use alongside other crash reporting SDKs (Firebase Crashlytics, Sentry, etc.).

ℹ️
For the most reliable behaviour, call Monitoor.configure() before initialising other crash reporting SDKs, so Monitoor's handlers are installed first in the chain.
