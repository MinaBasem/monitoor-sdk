Setup Guide

Getting Started

Install the SDK, add your API key, and send your first events in under five minutes.

Step 1 — Get your API key

Sign up at monitoor.io, create a project, then go to API Keys and generate a key.

  • Production key — prefix mn_live_ — use in App Store and TestFlight builds
  • Development key — prefix mn_dev_ — use in local development and the Simulator
⚠️
Key prefix must match environment. Using a mn_live_ key with environment: .development (or vice versa) causes the SDK to refuse to start. The mismatch is logged to the console in DEBUG builds.

Step 2 — Add the package in Xcode

  1. Open your project in Xcode. Navigate to your .xcodeproj or .xcworkspace.
  2. File → Add Package Dependencies… The package dependency dialog opens.
  3. Paste the repository URL into the search bar (top-right). 
    https://github.com/MinaBasem/monitoor-ios-sdk
    Press Return. Xcode fetches the package manifest.
  4. Set the dependency rule. Choose Up to Next Major Version starting from 1.0.0.
  5. Click Add Package. In the target selection sheet, tick your app target and click Add Package.

MonitoorSDK now appears under Package Dependencies in the Project Navigator.

Step 3 — Initialize the SDK

Call Monitoor.configure() once, as early as possible in your app's lifecycle — before any view appears.

SwiftUI

import SwiftUI
import MonitoorSDK

@main
struct MyApp: App {

    init() {
        Monitoor.configure(
            apiKey: "mn_live_your_key_here",
            options: MonitoorOptions(environment: .production)
        )
    }

    var body: some Scene {
        WindowGroup { ContentView() }
    }
}

UIKit — AppDelegate

import UIKit
import MonitoorSDK

@UIApplicationMain
class AppDelegate: UIResponder, UIApplicationDelegate {

    func application(
        _ application: UIApplication,
        didFinishLaunchingWithOptions launchOptions: [UIApplication.LaunchOptionsKey: Any]?
    ) -> Bool {

        Monitoor.configure(
            apiKey: "mn_live_your_key_here",
            options: MonitoorOptions(environment: .production)
        )

        return true
    }
}
ℹ️
Configure only once. Calling Monitoor.configure() more than once is silently ignored. Only the first call takes effect.

Step 4 — Verify it's working

On first launch after configuring, the SDK automatically sends a $app_open event. To confirm events are reaching the database:

  1. Start the ingest server: python3 server.py in the ingest-server/ folder.
  2. Build and run your app on a device or Simulator.
  3. Within 20 seconds, check the Event table in Neon — you should see a $app_open row.

In DEBUG builds, the SDK logs to the console. Look for [Monitoor] prefixed messages.

Development vs production setup

During development, point the SDK at your local ingest server instead of the production URL:

Monitoor.configure(
    apiKey: "mn_dev_your_dev_key",
    options: MonitoorOptions(
        ingestURL: URL(string: "http://192.168.1.42:8080")!,
        environment: .development
    )
)
💡
Finding your Mac's IP: Run ipconfig getifaddr en0 in Terminal. Your iPhone and Mac must be on the same Wi-Fi network. For the Simulator, use http://localhost:8080 instead.

SwiftUI Previews

Guard the configure call so it doesn't fire inside Xcode previews:

init() {
    guard !ProcessInfo.processInfo.environment.keys
        .contains("XCODE_RUNNING_FOR_PREVIEWS")
    else { return }

    Monitoor.configure(
        apiKey: "mn_dev_your_dev_key",
        options: MonitoorOptions(environment: .development)
    )
}

What happens on configure()

When Monitoor.configure() is called, the SDK performs the following in order:

  1. Validates the API key prefix against the specified environment.
  2. Loads or generates a persistent device_id UUID from the iOS Keychain.
  3. Opens the local SQLite event buffer in WAL mode.
  4. Uploads any pending crash reports from the previous launch.
  5. Installs crash signal handlers (if captureCrashes: true).
  6. Starts the StoreKit 2 transaction observer (if captureRevenue: true).
  7. Installs the UIViewController swizzle for automatic screen tracking (if captureScreens: true).
  8. Registers app lifecycle observers (foreground, background, terminate).
  9. Starts the flush timer.
  10. Enqueues a $app_open event.
