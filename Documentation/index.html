MonitoorSDK for iOS

Understand your users.
One line at a time.

MonitoorSDK is a lightweight, privacy-first analytics SDK for iOS. Drop it into any SwiftUI or UIKit app and start collecting events, button presses, screen views, revenue, and crashes — with no third-party dependencies and zero configuration.

What the SDK does

Every event is written to a local SQLite buffer on the device first, so nothing is ever lost — even when the device is offline. Events are then streamed to your Monitoor dashboard over HTTPS in batches.

Quick start

Step 1 — Add the Swift Package

In Xcode: File → Add Package Dependencies… Paste into the search bar at the top-right:

https://github.com/MinaBasem/monitoor-ios-sdk

Set the rule to Up to Next Major Version from 1.0.0. Click Add Package, tick your app target, click Add Package.

Step 2 — Get your API key

Sign up at monitoor.io, open your project, and navigate to API Keys. Generate one key for each environment:

PrefixEnvironmentUse for
mn_live_.productionApp Store, TestFlight
mn_dev_.developmentLocal dev, Simulator, your device

Step 3 — Store the key safely

🚨 Do NOT commit your API key to git

Your API key is a secret. Putting it directly in a Swift file and pushing it to GitHub means every visitor to your repo — including bots that scrape public repos for secrets every few minutes — can see it and send fake events to your dashboard. Don't do it.

Store it in a .env file at the root of your project, then make sure .env is in your .gitignore. Your future self will thank you. So will your data. 🙏

# .env  (never committed)
MONITOOR_API_KEY=mn_dev_your_key_here
# .gitignore  (this line saves careers)
.env
.env.local
.env.*.local

In Xcode, add it as a build environment variable (Product → Scheme → Edit Scheme → Run → Arguments → Environment Variables), then read it in Swift:

let apiKey = ProcessInfo.processInfo.environment["MONITOOR_API_KEY"] ?? ""

Step 4 — Configure in your app entry point

Call Monitoor.configure() once, before any view appears. Calling it a second time is silently ignored.

SwiftUI

import SwiftUI
import MonitoorSDK

@main
struct MyApp: App {

    init() {
        let apiKey = ProcessInfo.processInfo.environment["MONITOOR_API_KEY"] ?? ""

        Monitoor.configure(
            apiKey: apiKey,
            options: MonitoorOptions(
                environment: .development  // change to .production for release
            )
        )
    }

    var body: some Scene {
        WindowGroup { ContentView() }
    }
}

UIKit — AppDelegate

import UIKit
import MonitoorSDK

@UIApplicationMain
class AppDelegate: UIResponder, UIApplicationDelegate {

    func application(
        _ application: UIApplication,
        didFinishLaunchingWithOptions launchOptions: [UIApplication.LaunchOptionsKey: Any]?
    ) -> Bool {

        let apiKey = ProcessInfo.processInfo.environment["MONITOOR_API_KEY"] ?? ""
        Monitoor.configure(apiKey: apiKey, options: MonitoorOptions(environment: .development))
        return true
    }
}

Step 5 — Verify it's working

Build and run. The SDK immediately sends a $app_open event. Within 30 seconds it appears in your Monitoor dashboard. In DEBUG builds, look for [Monitoor] lines in the Xcode console.

💡
To force an immediate flush during testing instead of waiting for the timer: Monitoor.flush()

Tracking examples

Every tracker below is independent — add as many or as few as you need. All examples use a music player app to keep the context consistent.

👆
Button presses
SwiftUI: .monitoorTap() modifier  ·  UIKit: MonitoorButton or .monitoor_trackTaps()
Manual

Attach .monitoorTap() to any SwiftUI button or tappable view. It fires a simultaneousGesture alongside the button's own action — your existing code is not touched.

// ── SwiftUI ───────────────────────────────────────────────────────────

// Basic button
Button("Play") { player.play() }
    .monitoorTap("play_tapped")

// Button with context properties
Button("Add to Playlist") { addToPlaylist(track) }
    .monitoorTap("add_to_playlist_tapped", properties: [
        "track": track.title,
        "artist": track.artist
    ])

// Dynamic event name based on state
Button { player.toggleLike(track) } label: {
    Image(systemName: liked ? "heart.fill" : "heart")
}
.monitoorTap(liked ? "track_unliked" : "track_liked")

// On a tappable card, not a Button
NowPlayingCard(track: currentTrack)
    .onTapGesture { showNowPlaying = true }
    .monitoorTap("now_playing_opened", properties: ["source": "mini_player"])

// Inside a ForEach list
ForEach(playlists) { playlist in
    Button { play(playlist) } label: { PlaylistRow(playlist: playlist) }
        .monitoorTap("playlist_played", properties: ["name": playlist.name])
}

// ── UIKit ─────────────────────────────────────────────────────────────

// Subclass for new buttons
let shuffleBtn = MonitoorButton(eventName: "shuffle_tapped")
let buyBtn     = MonitoorButton(eventName: "buy_tapped", properties: ["plan": "annual"])

// Extension for existing buttons you can't subclass
override func viewDidLoad() {
    super.viewDidLoad()
    signInButton.monitoor_trackTaps(eventName: "sign_in_tapped")
    shareButton.monitoor_trackTaps(eventName: "share_tapped", properties: ["screen": "profile"])
}
📱
Screen views
UIKit: automatic via swizzle  ·  SwiftUI: .monitoorScreen() modifier
Auto + Manual

UIKit view controllers are tracked automatically — no code needed. For SwiftUI, attach .monitoorScreen() to each screen-level view. This only records the screen's name as a string — no screenshots, no recordings.

// ── UIKit — zero code required ─────────────────────────────────────────
// LibraryViewController  → tracked as "Library"
// PlaylistDetailVC       → tracked as "PlaylistDetail"
// NowPlayingController   → tracked as "NowPlaying"
// System containers (UINavigationController, etc.) are excluded automatically.

// ── SwiftUI — add modifier to each screen ─────────────────────────────
struct LibraryView: View {
    var body: some View {
        ScrollView { /* track list */ }
            .monitoorScreen("Library")
    }
}

struct PlaylistDetailView: View {
    let playlist: Playlist

    var body: some View {
        List(playlist.tracks) { TrackRow(track: $0) }
            .monitoorScreen("PlaylistDetail", properties: [
                "name":        playlist.name,
                "track_count": playlist.tracks.count
            ])
    }
}

// Sheets and modals work the same way
struct NowPlayingView: View {
    var body: some View {
        VStack { /* player UI */ }
            .monitoorScreen("NowPlaying")
    }
}
📡
Custom events
Monitoor.track("event_name", properties: [...])
Manual

Track any action that isn't a button tap or screen view. Call Monitoor.track() anywhere — in view models, closures, onChange, async functions. Thread-safe.

// Simple event — something happened
Monitoor.track("onboarding_completed")
Monitoor.track("library_empty_state_shown")

// Event with rich context
Monitoor.track("song_played", properties: [
    "title":   track.title,
    "artist":  track.artist,
    "source":  "library",      // where the user found it
    "shuffle": isShuffled        // Bool
])

// Tracking feature adoption
Monitoor.track("equalizer_opened")
Monitoor.track("theme_changed", properties: ["theme": selectedTheme])

// Tracking errors and empty states
Monitoor.track("import_failed", properties: ["reason": error.localizedDescription])
Monitoor.track("search_no_results", properties: ["query": searchText])

// In a SwiftUI .onChange
TextField("Search", text: $query)
    .onChange(of: query) { _, q in
        if !q.isEmpty { Monitoor.track("search_started") }
    }

// In an async function
func importFiles(urls: [URL]) async {
    do {
        let count = try await library.import(urls)
        Monitoor.track("files_imported", properties: ["count": count])
    } catch {
        Monitoor.track("import_failed")
    }
}
⏱️
Timed events
Monitoor.startTimer("name") then Monitoor.track("name")
Manual

Measure how long something takes. Call startTimer() at the start, then track() with the same name at the end. The elapsed time is attached automatically as $duration (seconds as a Double).

// Measure onboarding duration
// Called when the onboarding flow begins
Monitoor.startTimer("onboarding_flow")

// Called when the user finishes — $duration is attached automatically
Monitoor.track("onboarding_flow")
// → event contains "$duration": 47.3  (seconds)

// Measure file import speed
Monitoor.startTimer("file_import")
let count = try await library.import(urls)
Monitoor.track("file_import", properties: ["file_count": count])
// → "$duration": 1.84, "file_count": 12

// Measure time to first play after opening the app
Monitoor.startTimer("time_to_first_play")
// ... user browses library ...
Button("Play") { player.play(track) }
    .monitoorTap("time_to_first_play")
// → "$duration": 23.5  (seconds from app open to first play)

Session duration
Automatic on background  ·  Read anytime via Monitoor.sessionDuration
Auto + Manual

The SDK automatically attaches $session_duration_s to every $app_background event. You can also read the current elapsed time at any point in your code.

// Read current session time
let seconds = Monitoor.sessionDuration   // e.g. 142.7
let minutes = Int(Monitoor.sessionDuration / 60)

// Include it in your own events
Monitoor.track("paywall_shown", properties: [
    "session_duration_s": Monitoor.sessionDuration,
    "trigger": "feature_gate"
])

// Display it in a debug overlay during development
Text("Session: \(Int(Monitoor.sessionDuration))s")

// The SDK also sends this automatically on every background:
// $app_background  →  { "$session_duration_s": 247.3 }
👤
User identity
identify() · setUserProperties() · reset()
Manual

The SDK is anonymous by default. Optionally link events to your users. The user ID is SHA-256 hashed on-device — Monitoor never sees the plaintext ID.

// After sign-in — link all future events to this user
func onSignInSuccess(user: User) {
    Monitoor.identify(userId: user.id)  // hashed on-device, never plaintext

    Monitoor.setUserProperties([
        "plan":             user.plan,       // "free", "pro"
        "account_age_days": user.ageDays,   // Int
        "locale":           user.locale      // "en_US"
    ])

    Monitoor.track("sign_in_completed", properties: ["method": "email"])
}

// When the subscription changes
func onUpgraded(to plan: String) {
    Monitoor.setUserProperties(["plan": plan])
    Monitoor.track("plan_upgraded", properties: ["plan": plan])
}

// On sign-out — clear identity, new anonymous device ID, new session
func onSignOut() {
    Monitoor.track("sign_out_tapped")
    auth.signOut()
    Monitoor.reset()
}
💰
Revenue
StoreKit 2: automatic  ·  StoreKit 1 / other: Monitoor.trackRevenue()
Auto + Manual

StoreKit 2 transactions are captured with zero code when captureRevenue: true (the default). For StoreKit 1 or any non-Apple payment, call trackRevenue() manually.

// ── StoreKit 2 — no code needed ────────────────────────────────────────
// The SDK subscribes to Transaction.updates automatically.
// Every verified purchase fires a $revenue event.

// ── StoreKit 1 ────────────────────────────────────────────────────────
func paymentQueue(
    _ queue: SKPaymentQueue,
    updatedTransactions transactions: [SKPaymentTransaction]
) {
    for tx in transactions where tx.transactionState == .purchased {
        Monitoor.trackRevenue(
            productId:     tx.payment.productIdentifier,
            amount:        product.price.doubleValue,
            currency:      Locale.current.currency?.identifier ?? "USD",
            type:          .subscription,
            transactionId: tx.transactionIdentifier ?? UUID().uuidString
        )
        queue.finishTransaction(tx)
    }
}

// ── Consumable in-app purchase ─────────────────────────────────────────
Monitoor.trackRevenue(
    productId:     "com.myapp.coins_100",
    amount:        0.99,
    currency:      "USD",
    type:          .consumable,
    transactionId: receipt.transactionId
)

Crash reporting
Fully automatic — zero code required
Automatic

Signal handlers and an uncaught exception handler are installed when captureCrashes: true (the default). Crash reports are written to disk in the signal handler and uploaded on the next app launch.

// That's it. configure() handles everything.
Monitoor.configure(
    apiKey: apiKey,
    options: MonitoorOptions(
        captureCrashes: true  // default — captures SIGABRT, SIGSEGV, SIGBUS,
                               // SIGILL, SIGFPE, SIGTRAP, and NSExceptions
    )
)

// To disable (e.g. if you use another crash SDK like Crashlytics):
MonitoorOptions(captureCrashes: false)
🌐
Super properties
Global key/values merged into every event  ·  persisted across launches
Manual

Register once and the values attach to every subsequent event automatically — no need to repeat them on each track() call. Event-specific properties override super properties on key conflict.

// Register once (e.g. after sign-in)
Monitoor.registerSuperProperties([
    "app_tier":  "pro",
    "ab_cohort": "B"
])

// Every event now carries app_tier and ab_cohort automatically
Monitoor.track("song_played")

// Remove one, or clear them all
Monitoor.unregisterSuperProperty("ab_cohort")
Monitoor.clearSuperProperties()
🔒
Consent & opt-out
Runtime control for GDPR / App Store consent  ·  persisted across launches
Manual

Stop all collection at runtime. When opted out, nothing is captured or transmitted and the local buffer is purged.

// Wire to your consent banner
func onConsentChanged(granted: Bool) {
    granted ? Monitoor.optIn() : Monitoor.optOut()
}

if Monitoor.isOptedOut { /* collection is paused */ }
📡
Remote configuration
Dashboard-controlled capture flags  ·  no app update needed
Automatic

On launch the SDK fetches your API key's configuration from GET /v1/config and applies it at runtime. Toggle capture flags, the sampling rate, or retention from your dashboard and connected apps pick it up on their next launch — no rebuild required. Your local MonitoorOptions act as fallbacks until the config arrives and while offline.

// Nothing to call — configure() fetches and applies remote config.
// Dashboard changes to captureEvents / captureScreens / captureRevenue /
// sampleRate (mul) / retention take effect on the next app launch.

Key design principles

Zero event loss

Every event is written to a SQLite database on the device synchronously before track() returns. Events survive app kills, crashes, and weeks of offline use. They are delivered to the server when connectivity returns, up to 90 days after capture.

Anonymous first

No PII is collected by default. The SDK uses an anonymous device UUID stored in the iOS Keychain — not linked to any Apple identifier. User IDs are opt-in and SHA-256 hashed on-device before any transmission.

No direct database access

The SDK sends events over HTTPS to an ingest service. The ingest service holds database credentials server-side. Your database password never exists inside the iOS app.
